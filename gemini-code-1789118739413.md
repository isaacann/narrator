Build a modern, production-ready Text-to-Audio web application using Next.js (App Router), React, Tailwind CSS, and Lucide icons.

### Core Objectives
The app allows users to input or paste text (predominantly English mixed with Mandarin Chinese) and convert it into high-fidelity, natural, human-like speech.

### Tech Stack & Audio Engine
1. **Frontend**: Next.js App Router, Tailwind CSS, Lucide-React.
2. **TTS Backend**: Create an API route (`/api/tts`) that interfaces with an ultra-realistic TTS provider:
   - Implement this using **ElevenLabs API** (model: `eleven_multilingual_v2` for seamless English + Chinese mixed pronunciation) OR **OpenAI Audio API** (`tts-1-hd`).
   - Default to using the OpenAI TTS or ElevenLabs endpoint depending on available `.env.local` keys (`ELEVENLABS_API_KEY` or `OPENAI_API_KEY`).
   - Provide a zero-config fallback to the browser's native `window.speechSynthesis` API if no API key is provided, gracefully notifying the user while still functioning.

### Functional Requirements
1. **Text Area**:
   - Large auto-resizing text box with placeholder: "Paste your text here (supports English & Chinese)..."
   - Character and word count tracker.
   - Quick utility buttons: "Clear" and "Paste from Clipboard".
2. **Voice Selection**:
   - Voice dropdown/selector allowing users to choose between diverse natural voices (e.g., Alloy, Echo, Fable, Onyx, Nova, Shimmer for OpenAI; or Rachel, Adam, Antoni, Bella for ElevenLabs).
   - Speed/rate control slider (0.75x to 1.5x).
3. **Audio Playback Controls**:
   - When text is entered, reveal a prominent "Speak" / "Generate Audio" button.
   - Provide visual feedback during synthesis (subtle pulse or loading spinner).
   - Once audio is generated, display an interactive audio player with:
     - Play / Pause toggle.
     - Seekable progress scrubber with current time / total duration.
     - Download `.mp3` button.
     - Replay button.
4. **Bilingual Handling**:
   - Explicitly configure the TTS payload to handle mixed-language strings cleanly without crashing or skipping non-Latin characters.

### UI / UX Guidelines
- Clean, minimalist aesthetic (warm neutrals or clean dark mode).
- Centered layout, mobile-responsive card container with smooth micro-interactions.
- Clear error handling (e.g., API limits, empty input, network failures) via toast or inline alerts.

### Deliverables
- Fully implemented components (`page.tsx`, `components/AudioPlayer.tsx`, `components/VoiceSelector.tsx`, etc.).
- API route (`app/api/tts/route.ts`) with stream handling for binary audio responses.
- `.env.example` file detailing required keys.
- Step-by-step instructions in the terminal on how to run and test the app locally.
